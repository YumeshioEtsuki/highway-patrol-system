# 公路巡查数据采集系统 - 项目总结报告核心要点

## 📌 项目基本信息

**项目名称**: 公路巡查数据采集系统  
**技术栈**: FastAPI + MySQL + Web界面  
**开发周期**: 2025年11月-12月  
**项目定位**: 课程实践项目

---

## 🎯 一、项目概述

### 1.1 项目背景
公路巡查工作是保障道路安全的重要环节，传统纸质记录方式效率低、数据难统计。本系统通过数字化手段实现巡查记录的电子化管理，提高工作效率。

### 1.2 项目目标
- ✅ 实现巡查员移动端记录上报
- ✅ 提供管理员数据管理与统计分析
- ✅ 支持GPS定位、照片上传、状态跟踪
- ✅ 数据可视化与Excel导出

### 1.3 技术选型
| 技术领域 | 选择方案 | 理由 |
|---------|---------|------|
| 后端框架 | FastAPI | 现代异步框架，性能优秀，自动生成API文档 |
| 数据库 | MySQL 8.0 | 成熟稳定，支持事务，关系型数据易维护 |
| 前端 | HTML5 + CSS3 + JavaScript | 轻量级，无需额外编译，快速开发 |
| 认证 | JWT Token | 无状态认证，适合RESTful API |
| 数据可视化 | Chart.js | 开源免费，易于集成 |

## 🏗️ 二、需求分析

### 2.1 功能需求（已实现）

1. **用户管理**

2. **巡查记录管理**

   - 查看记录列表（带状态标识）
   - 记录详情展示
   - GPS自动定位（HTML5 Geolocation API）

3. **照片管理**
   - 多照片上传（支持批量）
   - 照片预览功能
   - 数据库BLOB存储
   - 照片查看接口

4. **GPS定位**
   - 前端自动获取经纬度
   - 定位精度显示
   - 地图链接跳转

#### 扩展功能（30%）
1. **数据统计分析（+10分）**
   - 总记录数、待处理数、处理中数、已解决数
   - 问题类型分布（饼图）
   - 严重程度分布（柱状图）
   - 每日上报趋势（折线图）

2. **筛选与搜索（+8分）**
   - 按状态筛选（pending/processing/resolved）
   - 按严重度筛选（1-5级）
   - 按日期范围筛选
   - 按关键词搜索（路段名称、问题描述）

3. **UI美化（+7分）**

   - Space Grotesk专业字体
   - 渐变背景与高级配色
   - 响应式布局

4. **数据导出（+5分）**
   - Excel格式导出
   - 包含完整记录信息
   - 中文表头

### 2.2 非功能需求
- **性能**: 页面加载<2秒，API响应<500ms
- **安全**: 密码哈希存储（bcrypt），SQL注入防护（参数化查询）

**关系说明**:
- User N:1 Department (一个部门有多个用户)
- RoadSegment N:1 Department (一个部门管理多个路段)
- InspectionRecord N:1 User (一个用户创建多条记录)
- InspectionRecord N:1 RoadSegment (一条记录关联一个路段)
- InspectionRecord N:1 ProblemType (一条记录关联一种问题类型)
- Photo N:1 InspectionRecord (一条记录可以有多张照片)

### 3.3 数据库表设计

#### 核心表结构

**1. User（用户表）**
```sql
CREATE TABLE User (
    user_id INT PRIMARY KEY AUTO_INCREMENT,
    username VARCHAR(50) NOT NULL UNIQUE,
    password VARCHAR(255) NOT NULL,      -- bcrypt哈希
    real_name VARCHAR(50) NOT NULL,
    phone VARCHAR(20) UNIQUE,
    email VARCHAR(100),
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    last_login DATETIME,
    role ENUM('inspector', 'admin') NOT NULL,
    department_id INT,
    FOREIGN KEY (department_id) REFERENCES Department(department_id)
);
```

**2. InspectionRecord（巡查记录表）**
```sql
CREATE TABLE InspectionRecord (
    record_id INT PRIMARY KEY AUTO_INCREMENT,
    user_id INT NOT NULL,
    upload_time DATETIME NOT NULL,
    latitude DECIMAL(10, 6),             -- GPS纬度
    longitude DECIMAL(10, 6),            -- GPS经度
    segment_id INT,
    problem_type_id INT,
    description TEXT,
    severity TINYINT,                    -- 1-5级
    status ENUM('pending', 'processing', 'resolved') DEFAULT 'pending',
    admin_process_time DATETIME,
    fix_time DATETIME,
    process_note TEXT,
    FOREIGN KEY (user_id) REFERENCES User(user_id),
    FOREIGN KEY (segment_id) REFERENCES RoadSegment(segment_id),
    FOREIGN KEY (problem_type_id) REFERENCES ProblemType(type_id)
);
```

**3. Photo（照片表）**
```sql
CREATE TABLE Photo (
    photo_id INT PRIMARY KEY AUTO_INCREMENT,
    record_id INT NOT NULL,
    photo_type ENUM('test_pictures', 'after_fix') NOT NULL,
    file_path VARCHAR(255) NOT NULL,     -- BLOB路径或云存储URL
    file_name VARCHAR(100),
    file_size INT,
    upload_time DATETIME DEFAULT CURRENT_TIMESTAMP,
    is_watermarked BOOLEAN DEFAULT TRUE,
    FOREIGN KEY (record_id) REFERENCES InspectionRecord(record_id)
);
```

### 4.2 技术难点与解决方案

#### 难点1: 前端GPS定位兼容性
**问题**: 部分浏览器不支持或用户拒绝授权  
**解决**: 
- 判断`navigator.geolocation`存在性
- 提供友好错误提示引导用户授权
- 支持手动输入GPS作为降级方案

#### 难点2: BLOB照片存储与检索
**问题**: MySQL BLOB存储大文件影响性能  
**解决**:
- 限制单张照片大小（5MB）
- 添加索引优化查询
- 未来可迁移至OSS云存储

#### 难点3: Token过期管理
**问题**: Token过期后用户体验不佳  
**解决**:
- 前端记录Token过期时间
- 请求前检查有效性
- 401响应自动跳转登录页

#### 难点4: 数据库连接池管理
**问题**: 高并发时连接数不足  
**解决**:
- 使用pymysql连接池
- 每次请求后显式关闭连接
- 设置合理的超时时间
