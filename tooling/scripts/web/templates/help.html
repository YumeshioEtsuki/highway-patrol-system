🎯 Quick Start

This tool helps you manage configuration variables across multiple environments (dev, test, demo, prod).

Basic Workflow

  1. Enter a configuration key (e.g., DEBUG, LOG_LEVEL)
  2. Review current values and recommended values for each environment
  3. Select which environments to update
  4. Apply changes - they're saved automatically to .env files
💡 Tip: Changes are immediately written to tooling/env/*.env files. No need to manually edit files!

🔧 Common Configuration Keys

Key Purpose Typical Values
DEBUG Enable debug mode True (dev/test), False (prod)
SKIP_DB_INIT Skip database initialization 0 (dev/test), 1 (prod)
LOG_LEVEL Logging verbosity DEBUG (dev), INFO (test/prod)
SECURE_MODE Enable security features 0 (dev/test), 1 (prod)
DEFAULT_ADMIN_PASSWORD Admin default password dev password (dev/test), empty (prod)

📂 File Locations

Configuration files are stored in:

  • tooling/env/local.dev.env - Development environment
  • tooling/env/local.test.env - Testing environment
  • tooling/env/local.demo.env - Demo environment
  • tooling/env/production.env - Production environment

✅ Best Practices

  • Never commit production secrets: Production values should be set directly on servers
  • Use environment-specific values: Dev should be permissive, prod should be restrictive
  • Document your keys: Add comments in .env files to explain what each variable does
  • Review before applying: Always check current values before overwriting
  • Test in dev first: Validate configuration changes in dev before applying to prod
⚠️ Warning: Changing configuration in production can affect running services. Always coordinate with your team before making production changes.

🛠️ Features

Smart Recommendations

The tool provides intelligent default values based on best practices:

  • Security settings stricter in production
  • Debug mode enabled in dev/test, disabled in prod
  • Database initialization skipped in production

View All Configurations

Click "View All Configurations" to see a complete table of all environment variables across all environments at once.

Custom Values

On the analysis page, you can apply custom values instead of recommendations. This is useful for:

  • Project-specific requirements
  • Testing specific configurations
  • Emergency overrides

❓ Troubleshooting

Changes not taking effect?

Restart your application after changing configuration files. Some apps cache environment variables at startup.

Can't find a configuration key?

Use the "View All Configurations" page to see all existing keys, or check .env.example for available options.

Validation failed?

Make sure your value format matches the expected type (string, number, boolean). Check for typos and extra spaces.
