公路巡查数据采集系统开发
前言：角色分工
一、项目概述
1.1 项目背景
公路养护部门需要定期巡查公路状况，发现并记录路面破损、护栏损坏、标志缺失等问题。传统的纸质记录方式存在诸多问题：
效率低：巡查员需要携带纸笔，回办公室后再整理
易丢失：纸质档案管理困难，照片与记录容易分离
难统计：无法快速统计问题类型、发生频率等数据
不直观：缺少位置信息，问题地点描述不准确
1.2 项目目标
开发一个基于微信小程序的移动数据采集系统，实现：
✅ 便捷记录：手机拍照、自动定位、快速填写信息
✅ 集中存储：所有数据存储在数据库，便于管理
✅ 快速查询：随时查看历史记录，支持筛选统计
✅ 数据准确：GPS定位准确记录问题位置
1.3 学习目标
通过本项目，你将：
掌握数据库设计的完整流程（最为重要内容）
从需求分析到概念设计（ER图）
从逻辑设计到物理实现（建表）
索引优化和性能调优
学习前后端分离架构
理解客户端-服务器架构
掌握RESTful API设计
学会前后端数据交互
了解移动应用开发
微信小程序开发基础
拍照、定位等手机功能调用
移动端用户体验设计
培养项目管理能力
团队协作与分工
版本控制与进度管理
文档编写与演示答辩

Q6：如何测试API接口？
A：推荐使用Postman：
下载Postman：https://www.postman.com/downloads/
创建请求： 
选择HTTP方法（GET/POST等）
填写URL（如 http://localhost:5000/api/patrol）
填写参数（GET用Params，POST用Body→raw→JSON）
发送请求：点击Send按钮
查看响应：在下方查看返回的JSON数据
示例：
POST http://localhost:5000/api/patrol
Body (raw, JSON):
{
  "user_id": 1,
  "location_desc": "国道G107",
  "problem_desc": "路面破损"
}

安装flaREDACTEDcors：
pip install flaREDACTEDcors

一旦发现，该项目零分处理
合理引用：
如果使用了开源代码或第三方库，要在文档中注明
参考的资料要列在参考文献中
12.2 安全提示
数据库安全：
不要把数据库密码写死在代码里
使用环境变量或配置文件
不要把包含密码的文件上传到公开平台
API安全：
对用户输入进行验证
防止SQL注入（使用参数化查询）
重要操作要验证用户身份
数据备份：
定期备份数据库
定期备份代码
建议使用Git进行版本控制
