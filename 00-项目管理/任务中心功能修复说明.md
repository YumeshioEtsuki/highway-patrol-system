# 任务中心功能修复说明

## 修复的问题

### 1. ✅ 性能指标收集失败
**问题原因**：`collect_performance_metrics` 任务依赖 `slow_query_logs` 表，该表不存在

**解决方案**：
- 简化性能指标收集，改用 `psutil` 库收集系统指标
- 收集 CPU、内存、磁盘使用率
- 收集 Redis 连接数和内存使用
- 不再依赖数据库表，避免表结构依赖

**安装的依赖**：
```bash
pip install psutil
```

### 2. ✅ 任务列表不显示/刷新无反应
**问题原因**：
- Celery `inspect()` 可能返回 None 或超时
- 没有从 Redis 读取已完成任务的结果

**解决方案**：
- 添加超时控制：`inspect(timeout=1.0)`
- 添加异常处理，即使 inspect 失败也不会中断
- 从 Redis 查询 `celery-taREDACTEDmeta-*` 键获取已完成任务
- 合并活跃任务、计划任务和已完成任务

### 3. ✅ AI 分析功能参数不匹配
**问题原因**：
- `check_photo_quality` 需要 `photo_path`，但前端/后端传的是 `photo_id`
- `analyze_patrol_record` 需要 3 个参数（record_id, description, photos），但只传了 `record_id`

**解决方案**：
- 修改 `CheckPhotoQualityRequest` 模型，使用 `photo_path` 参数
- 修改 `analyze_record_task` 路由，先从数据库查询记录详情（description 和 photos），再调用任务
- 添加记录不存在的 404 错误处理

## 已知限制

1. **AI 功能依赖 Ollama**：
   - 需要本地运行 Ollama 服务
   - 使用模型：`qwen:7b`
   - 如果 Ollama 不可用，任务会失败但不会影响其他功能

2. **任务列表限制**：
   - 默认只显示最近 20 个任务
   - Redis 中的任务元数据有过期时间
   - 旧任务可能不显示

3. **性能指标收集**：
   - 依赖 psutil 库
   - 如果未安装，会返回简化的结果
   - 不再保存到数据库（避免表结构依赖）
