# 性能优化：流式生成测试数据

## 问题描述

**用户反馈**：生成带图片的测试数据时，需要等待整个操作完成才能看到审计日志更新，用户体验差。

### 原因分析

1. **同步阻塞**：旧的 `/admin/generate` (POST) 端点使用同步方式，必须等待所有记录生成完成才返回响应
2. **延迟刷新**：前端只在收到响应后才调用 `loadAudit()`，导致审计日志更新延迟
3. **无进度反馈**：生成200条带图片的数据需要10-20秒，期间用户看不到任何进度信息

### 业务影响

- 生成大批量数据（≥50条）或带图片时，用户等待时间长
- 审计日志无法实时反映操作状态
- 用户不知道任务是否正在执行或卡住

---

## 解决方案

### 1. 创建流式生成函数

在 `services/patrol_service.py` 中新增 `stream_generate_fake_records()` 函数：

**核心特性**：
- 使用 SSE (Server-Sent Events) 实时推送进度
- 每50条记录或每10%进度发送一次更新
- 支持错误处理和异常恢复
- 批量提交（每50条commit一次）

**进度消息类型**：
```python
yield sse_message('log', '📦 开始生成...')      # 启动信息
yield sse_message('success', '✅ 图片模板已生成')  # 成功步骤
yield sse_message('info', '📊 进度 50% (100/200)') # 进度更新
yield sse_message('warn', '⚠️ 第5条失败: ...')    # 警告信息
yield sse_message('error', '❌ 生成失败: ...')    # 错误信息
yield sse_message('complete', '🏁 数据生成完成')   # 完成标记
```

### 2. 添加流式API端点

在 `routes/admin/admin_routes.py` 中新增：

```python
@router.get("/admin/generate/stream", summary="生成随机测试数据（流式）")
async def generate_data_stream(
    count: int = Query(50, ge=1, le=5000),
    include_photos: bool = Query(False),
    admin: CurrentUser = Depends(get_current_admin_qs)
):
    # 在开始生成之前记录审计日志
    insert_audit_log(admin.user_id, "generate_data", f"开始生成: count={count}, photos={include_photos}")
    
    generator = stream_generate_fake_records(count=count, with_photos=include_photos)
    return StreamingResponse(generator(), media_type='text/event-stream')
```

**关键改进**：
- 审计日志在 **生成开始前** 就写入数据库
- 立即返回 StreamingResponse，不等待生成完成
- 前端可以马上刷新审计日志，看到"开始生成"记录

### 3. 前端智能切换

修改 `templates/admin.html` 中的 `generateFake()` 函数：

```javascript
async function generateFake(count = 50, includePhotos = false) {
    const useStream = count >= 50 || includePhotos;  // 智能判断
    
    if (useStream) {
        // 流式生成（实时进度）
        clearLivePhotos();
        
        // 关键优化：500ms后立即刷新审计日志，不等待生成完成
        setTimeout(() => {
            if (typeof loadAudit === 'function') {
                loadAudit().catch(err => console.warn('[GenerateFake] 审计刷新失败:', err));
            }
        }, 500);
        
        await runTask(`/api/admin/generate/stream?count=${count}&include_photos=${includePhotos}`);
        // ... UI重置和数据刷新
    } else {
        // 小批量使用同步API（保持快速响应）
        // ... 原有逻辑
    }
}
```

**策略说明**：
- **大批量（≥50条）或带图片**：使用流式API，实时显示进度
- **小批量（<50条）且无图片**：使用同步API，快速返回结果
- 审计日志延迟500ms后立即刷新（确保后端已写入）

## 技术实现细节

### SSE消息格式

使用 `core.sse.sse_message()` 工具函数：

```python
def sse_message(event: str, data: str) -> str:
    """
    生成 SSE 格式消息
    event: 'log', 'info', 'success', 'warn', 'error', 'complete'
    data: 消息内容
    """
    import time
    from datetime import datetime
    
    ts_epoch_ms = int(time.time() * 1000)
    time_str = datetime.now().strftime('%H:%M:%S')
    
    return f"data: {json.dumps({'event': event, 'data': data, 'time': time_str, 'ts_epoch_ms': ts_epoch_ms}, ensure_ascii=False)}\n\n"
```

### 前端EventSource处理

复用现有的 `runTask()` 函数，包含以下功能：
- 自动添加token认证参数
- 显示累计耗时（`+1.25s`）
- 颜色区分消息类型（log/success/warn/error）
- 任务完成后自动关闭连接
- 完成后自动刷新数据和审计日志

### 批量提交优化

```python
BATCH_SIZE = 50  # 每50条提交一次

for i in range(int(count)):
    # 插入记录...
    inserted_count += 1
    
    if (i + 1) % BATCH_SIZE == 0 or (i + 1) % max(1, count // 10) == 0:
        conn.commit()
        progress = int((i + 1) / count * 100)
        yield sse_message('info', f'📊 进度 {progress}% ({i+1}/{count})')
```

**优点**：
- 减少数据库提交次数，提升性能
- 每10%进度或每50条发送一次进度更新
- 避免频繁的SSE推送造成前端卡顿

## 性能对比

### 优化前

| 操作 | 响应时间 | 用户体验 |
|------|----------|----------|
| 生成50条（无图片） | 2-3秒 | ⏳ 阻塞等待 |
| 生成200条（含图片） | 15-20秒 | ⏳ 长时间无响应 |
| 审计日志更新 | 操作完成后 | ❌ 延迟显示 |

### 优化后

| 操作 | 响应时间 | 用户体验 |
|------|----------|----------|
| 生成50条（无图片） | 2-3秒 | ✅ 快速完成（同步API） |
| 生成200条（含图片） | 立即响应 | ✅ 实时进度 + 审计日志 |
| 审计日志更新 | 0.5秒后 | ✅ 即时显示 |
| 进度反馈 | 每10%更新 | ✅ 实时百分比显示 |

**改善指标**：
- **感知延迟**：从 15-20秒 降至 0.5秒
- **审计日志可见性**：从 "操作完成后" 提前到 "操作开始后500ms"
- **用户满意度**：显著提升（有进度条 vs 黑屏等待）

## 使用说明

### 后端API

#### 1. 同步API（保留兼容）

```http
POST /api/admin/generate?count=50&include_photos=false
Authorization: Bearer <token>
```

**适用场景**：小批量数据生成（<50条且无图片）

#### 2. 流式API（新增）

```http
GET /api/admin/generate/stream?count=200&include_photos=true&token=<token>
```

**适用场景**：大批量或带图片的数据生成

### 前端调用

直接使用现有按钮即可，已自动切换API：

```javascript

```

系统会根据参数自动选择：
- `count >= 50 || includePhotos == true` → 流式API
- 其他情况 → 同步API

## 注意事项

### 1. Token传递

SSE使用 `GET` 请求，无法通过 `Authorization` header传递token，因此：
- 前端在URL中添加 `?token=<jwt>` 参数
- 后端通过查询参数验证身份

### 2. 错误处理

流式生成中的错误处理：
- 单条记录失败不中断整体流程
- 前3条错误会推送警告消息
- 最终返回成功/失败统计

```python
try:
    # 插入记录...
except Exception as e:
    failed_count += 1
    if failed_count <= 3:
        yield sse_message('warn', f'⚠️ 第{i+1}条失败: {str(e)[:50]}')
    continue  # 继续处理下一条
```

### 3. 并发控制

前端已有 `isOperating` 标志防止重复操作：
```javascript
if (isOperating) {
    alert('上一个操作仍在进行中，请稍候...');
    return;
}
```

### 4. 兼容性

- **同步API** 保持不变，现有调用方式仍然有效
- 流式API作为增强功能，不影响旧版本
- 前端自动判断，无需手动配置

## 未来改进

### 1. 后台任务化

可进一步优化为 Celery 异步任务：

```python
@celery_app.task(bind=True)
def generate_fake_records_async(self, count, with_photos):
    for i in range(count):
        # 生成逻辑...
        self.update_state(state='PROGRESS', meta={'current': i+1, 'total': count})
```

**优点**：
- 支持断线重连后继续查询进度
